# Binance Data Collector

Автономный комплекс непрерывного сбора рыночных данных с Binance: тики, свечи, технические индикаторы и фичи биржевого стакана — в хранилище, готовое для бэктестинга и обучения моделей.

.NET 8, PostgreSQL 16, Docker, CI/CD через GitHub Actions.

---

## Что делает

- **Отбирает пары сам.** Сканер раз в день выбирает топ-40 самых ликвидных и волатильных пар.
- **Собирает тики в реальном времени** через WebSocket и складывает их в партиционированную таблицу.
- **Агрегирует свечи и считает индикаторы** (RSI, MACD, CVD) непрерывно, по мере поступления данных.
- **Собирает фичи стакана**: дисбаланс bid/ask, ликвидность у цены, спред, стенки. Сырой L2 не хранится — только производные числа.
- **Чинит себя сам.** Аудиторы находят дыры от обрывов связи и докачивают недостающие тики; свечи по ним пересчитываются.
- **Следит за диском.** Ротация по размеру: на диске всегда столько истории, сколько влезает, а не фиксированное число месяцев.
- **Показывает данные.** Биржевой график со свечами и индикаторами, панель проверок качества данных.

## Интерфейс (DataManager)

| Страница | Что там |
| :--- | :--- |
| **Home** (главная) | Статус системы, размеры и подключения БД, серверы Hangfire. Сводка **Months (Trades)** — по каждому прошедшему и текущему месяцу: расположение партиции (горячий SSD / холодный HDD) и печать месяца (Sealed с датой либо причина, почему ещё не закрыт). При недоступности запроса (таймаут под нагрузкой) панель показывает «данные временно недоступны», отличая это от честного отсутствия партиций. БД-панели обновляются раз в 5 с, сводка месяцев — раз в 120 с. |
| **Dashboard** | Пункт меню под будущую страницу; пока показывает заглушку «в разработке» со ссылками на готовые разделы. |
| **Chart** | Свечи 15м / 1ч / 4ч / 1д / 1нед, MA поверх цены, RSI / MACD / CVD отдельными панелями. Обновление раз в 3 секунды. |
| **Data Quality** | 18 проверок качества данных в 4 группах, запуск по кнопке, живой прогресс |
| **Archive** | Скачивание и импорт исторических архивов Binance |
| **Inspector** | Просмотр содержимого скачанных архивов |
| **Hangfire** | Состояние очередей и фоновых задач |

Доступ разграничен ролями `Viewer` / `Operator` / `Admin` через Azure AD B2C.

## Стек

**Общее:** C# / .NET 8 · PostgreSQL 16 + PgBouncer · Hangfire (отдельная БД для очередей) · RabbitMQ · SignalR · Serilog + Seq · Dapper + хранимые процедуры · Docker Compose · GitHub Actions + GHCR

**Только прод:** Traefik (TLS) · Cloudflare Tunnel (без проброса портов) · Uptime Kuma · Ubuntu Server

**Тесты:** xUnit · Moq · Testcontainers (интеграционные тесты гоняются на настоящем PostgreSQL с боевой схемой)

## Запуск локально

```bash
./docker/dev-start.sh    # PostgreSQL, PgBouncer, RabbitMQ, Seq
./docker/dev-stop.sh
```

Схема БД и служебная база Hangfire создаются автоматически на чистом томе из `docker/postgres/init/`. Worker и DataManager запускаются из IDE как обычные .NET-процессы.

Подробности — [`docs/dev/ARCHITECTURE_DEV.md`](./docs/dev/ARCHITECTURE_DEV.md).

### Что происходит после запуска

1. Worker сканирует рынок и наполняет `TrackedSymbols`.
2. Подписывается на WebSocket — тики идут в `Trades`.
3. Раз в минуту тики сворачиваются в свечи, раз в 2 минуты по ним считаются индикаторы.
4. Параллельно пишутся фичи стакана.
5. Открывайте `http://localhost:7002` → **Chart**: данные появляются на графике по мере накопления.

Историю за прошлые месяцы можно догрузить из архивов Binance на странице **Archive** — сбор при этом останавливать не нужно.

## Demo-окружение

Самодостаточный стек с уже наполненной БД — без сбора из Binance и без внешнего провайдера входа. Нужен только Docker (образы под amd64 и arm64, включая Apple Silicon). В БД предзагружен срез **BTCUSDT за февраль 2026**: свечи, индикаторы, журнал покрытия и печать закрытого месяца — сразу видны график, панель Months и проверки Data Quality. Вход локальный с выбором роли (`Authentication:Mode=Demo`) вместо Azure B2C, realtime-сбор выключен (`Collectors:Enabled=false`), данные — из seed (`docker/postgres/seed/`), а не из сети.

Пошаговый запуск по системам:

- **Linux** — [`docs/dev/DEMO_LINUX.md`](./docs/dev/DEMO_LINUX.md)
- **Windows** — [`docs/dev/DEMO_WINDOWS.md`](./docs/dev/DEMO_WINDOWS.md)
- **macOS** — [`docs/dev/DEMO_MACOS.md`](./docs/dev/DEMO_MACOS.md)

## Схема базы данных

Единый baseline `docker/postgres/init/02_baseline.sql` (генерируемый `pg_dump`-снимок) применяется автоматически на чистом томе. Изменения в существующую БД накатывает раннер `docker/postgres/migrate.sh` по журналу `schema_migrations`; CI-страж не пускает схему, разошедшуюся с миграциями ([ADR 0013](./docs/adr/0013-schema-baseline-and-migration-automation.md)).

Все растущие таблицы партиционированы помесячно **по одной сетке** — месяц дропается из всех сразу, поэтому свечей без тиков, из которых они посчитаны, не бывает.

Модель данных — [`docs/common/03_database.md`](./docs/common/03_database.md).

## Развёртывание

Push в `master` → GitHub Actions собирает и прогоняет тесты (`ubuntu-latest`), затем self-hosted runner на прод-сервере собирает образы, пушит в GHCR и перезапускает стек. Pull Request проходит только сборку и тесты, деплой не трогает.

Подробности — [`docs/prod/04_deployment.md`](./docs/prod/04_deployment.md).
