# Документация: 03 - База данных (PostgreSQL)

Этот документ описывает структуру, логику и взаимодействие компонентов базы данных `market_analytics`, работающей на PostgreSQL.

## 1. Концепция и архитектура данных

База данных спроектирована по принципу **"от сырых данных к агрегированным"**. Это позволяет хранить как максимально детализированную "сырую" информацию (тиковые сделки), так и предварительно обработанные, готовые для быстрого анализа данные (минутные свечи).

**Поток данных внутри базы:**
1.  **Поступление:** Все данные начинаются как тиковые сделки, которые непрерывно поступают в таблицу `"Trades"`. Это "входная воронка" системы.
2.  **Агрегация:** Специализированная функция (`sp_aggregate_trades_to_ohlcv`) регулярно читает новые данные из `"Trades"` и "сворачивает" их в минутные свечи, записывая результат в `"Ohlcv_1min"`.
3.  **Управление:** Список валютных пар, которые подлежат сбору, динамически управляется через таблицу `"TrackedSymbols"`.

Эта структура позволяет эффективно разделять нагрузку: быстрая запись тиков не мешает медленным аналитическим запросам к свечам.

## 2. Описание таблиц

### `public."Trades"`
- **Назначение:** Хранилище сырых, немодифицированных тиковых данных. Каждая запись — это одна сделка, прошедшая на бирже.
- **Структура:**
| Поле | Тип | Описание |
| :--- | :--- | :--- |
| **`"TradeId"`** | `BIGINT` | **(Часть PK)** Уникальный ID сделки от Binance. |
| **`"Symbol"`** | `VARCHAR(20)` | **(Часть PK)** Валютная пара (например, 'BTCUSDT'). |
| `"Price"` | `DECIMAL(18,8)` | Цена, по которой прошла сделка. |
| `"Quantity"` | `DECIMAL(28,8)` | Объем сделки в базовой валюте (например, в BTC). |
| `"QuoteQuantity"` | `DECIMAL(28,8)` | Объем сделки в котируемой валюте (например, в USDT). |
| `"TradeTime"` | `BIGINT` | Unix-время сделки в миллисекундах (UTC). |
| `"IsBuyerMaker"` | `BOOLEAN` | `true`, если покупатель был мейкером (пассивный ордер). |
| `"IsBestMatch"` | `BOOLEAN` | `true`, если сделка была по лучшей цене в стакане. |
| `"OrderId"` | `BIGINT` | ID ордера, к которому относится сделка. |
| `"IsMyTrade"` | `BOOLEAN` | (Будущее использование) `true`, если это личная сделка. |
- **Ключевые индексы:**
  - `PK ("TradeId", "Symbol")`: Обеспечивает уникальность каждой сделки для каждой пары.
  - `IX_Trades_Symbol_TradeTime`: Ускоряет выборку сделок по паре за период, что критически важно для агрегации.

### `public."Ohlcv_1min"`
- **Назначение:** Хранилище агрегированных, готовых к анализу данных. Каждая запись — это одна 1-минутная свеча (Open, High, Low, Close, Volume).
- **Структура:**
| Поле | Тип | Описание |
| :--- | :--- | :--- |
| **`"Symbol"`** | `VARCHAR(20)` | **(Часть PK)** Валютная пара. |
| **`"OpenTime"`** | `BIGINT` | **(Часть PK)** Unix-время **начала** минуты (кратно 60000). |
| `"OpenPrice"` | `DECIMAL(18,8)` | Цена первой сделки в этой минуте. |
| `"HighPrice"` | `DECIMAL(18,8)` | Максимальная цена за эту минуту. |
| `"LowPrice"` | `DECIMAL(18,8)` | Минимальная цена за эту минуту. |
| `"ClosePrice"` | `DECIMAL(18,8)` | Цена последней сделки в этой минуте. |
| `"Volume"` | `DECIMAL(28,8)` | Суммарный объем всех сделок за минуту. |

### `public."TrackedSymbols"`
- **Назначение:** Управляющая таблица. Определяет, для каких валютных пар система должна активно собирать данные.
- **Структура:**
| Поле | Тип | Описание |
| :--- | :--- | :--- |
| **`"Symbol"`** | `VARCHAR(20)` | **(PK)** Валютная пара. |
| `"IsActive"` | `BOOLEAN` | **Ключевое поле.** `true`, если сборщик (`Collector`) должен работать с этой парой. |
| `"DateAdded"` | `TIMESTAMPTZ` | Дата и время (UTC), когда пара была впервые добавлена. |
| `"LastScanned"` | `TIMESTAMPTZ` | Дата и время (UTC), когда сканер (`Scanner`) в последний раз видел эту пару в ТОПе. |

### `public."Ohlcv_Features"`
- **Назначение:** "Витрина данных". Хранит рассчитанные технические индикаторы (признаки), готовые для анализа и подачи в модели машинного обучения.
- **Структура:**
| Поле | Тип | Описание |
| :--- | :--- | :--- |
| **`"Symbol"`** | `VARCHAR(20)` | **(Часть PK)** Валютная пара. |
| **`"OpenTime"`** | `BIGINT` | **(Часть PK)** Unix-время начала свечи. |
| `"RSI_14"` | `DECIMAL(10, 4)`| Значение RSI с периодом 14. |
| `"MACD_Signal"` | `DECIMAL(18, 8)`| Сигнальная линия MACD(12,26,9). |
| `"MACD_Hist"` | `DECIMAL(18, 8)`| Гистограмма MACD(12,26,9). |
| `"MA_1051200"` | `DECIMAL(18, 8)`| 2-летняя скользящая средняя. |
| `"MA_201600"` | `DECIMAL(18, 8)`| 200-недельная скользящая средняя. |
| `"CVD"` | `DECIMAL(28, 8)`| Кумулятивная дельта объема на момент закрытия свечи. |

## 3. Описание функций (хранимых процедур)

### `public.sp_bulk_insert_trades(...)`
- **Задача:** Максимально быстро и эффективно вставить большую пачку новых сделок в таблицу `"Trades"`.
- **Логика:** Принимает на вход массивы данных, "разворачивает" их через `UNNEST` и выполняет `INSERT ... ON CONFLICT DO NOTHING` для предотвращения ошибок дубликатов.
- **Взаимодействие:** `[Пишет]` -> `"Trades"`.

### `public.sp_update_tracked_symbols(...)`
- **Задача:** Атомарно обновить список активных для отслеживания пар.
- **Логика:** Сначала деактивирует все старые пары (`UPDATE`), затем вставляет или обновляет (`INSERT ... ON CONFLICT DO UPDATE`) все пары из нового списка.
- **Взаимодействие:** `[Читает и Пишет]` -> `"TrackedSymbols"`.

### `public.sp_aggregate_trades_to_ohlcv()`
- **Задача:** Выполнять агрегацию тиков в минутные свечи.
- **Логика:** Находит новые тики, агрегирует их во временную таблицу, а затем использует `INSERT ... ON CONFLICT DO UPDATE` для "умной" вставки/обновления свечей в `"Ohlcv_1min"`.
- **Взаимодействие:** `[Читает]` -> `"Trades"`, `[Пишет]` -> `"Ohlcv_1min"`.

### `public.sp_upsert_ohlcv_features(...)`
- **Задача:** Максимально быстро и эффективно вставить/обновить пачку рассчитанных индикаторов в таблицу `"Ohlcv_Features"`.
- **Логика:** Принимает на вход массивы данных для каждого индикатора, "разворачивает" их и выполняет `INSERT ... ON CONFLICT DO UPDATE`, чтобы атомарно обновить витрину данных.
- **Взаимодействие:** `[Пишет]` -> `"Ohlcv_Features"`.
