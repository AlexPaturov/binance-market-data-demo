# Документация: 04 - Развертывание и CI/CD

Этот документ описывает процесс автоматического развертывания приложения `BinanceDataCollector` с помощью GitHub Actions и Docker.

## 1. Обзор Пайплайна (CI/CD)

Система использует **CI/CD (Continuous Integration / Continuous Deployment)** пайплайн на базе **GitHub Actions**. Это означает, что каждое изменение, отправленное в основную ветку репозитория, автоматически запускает процесс сборки, тестирования и развертывания новой версии приложения.

- **Триггер:** `git push` в ветку `master` (или `main`).
- **Среда выполнения:** Пайплайн выполняется на **Self-hosted Runner**, который установлен непосредственно на нашем сервере. Это решает проблему "серого" IP и ускоряет сборку.

**Основные этапы пайплайна:**
1.  **Checkout:** Скачивание последней версии исходного кода на сервер.
2.  **Login:** Авторизация в GitHub Container Registry (ghcr.io).
3.  **Build & Push:** Сборка .NET-приложения и создание Docker-образа на основе `Dockerfile`. Готовый образ загружается в GitHub Container Registry.
4.  **Deploy:** Выполнение команды `docker compose up -d` на сервере. Docker Compose автоматически скачивает новую версию образа и перезапускает только контейнер с приложением.

## 2. Ключевые файлы в репозитории

Для работы пайплайна в репозитории должны присутствовать следующие файлы:

1.  **`.github/workflows/deploy.yml`**: Главный скрипт, описывающий все шаги CI/CD.
2.  **`Dockerfile`**: "Чертеж" для сборки Docker-образа нашего .NET-приложения. Должен находиться в корне репозитория.
3.  **`.dockerignore`**: Файл, указывающий, какие файлы и папки не нужно копировать в Docker-образ, чтобы ускорить сборку.
4.  **`docker-compose.yml`**: "Пульт управления" системой на сервере. **Важно:** этот файл копируется на сервер **один раз** вручную. В репозитории может храниться его шаблон. Версия на сервере должна использовать директиву `image:`, а не `build:`.

## 3. Первоначальная настройка (выполняется один раз)

### 3.1. Настройка GitHub Secrets
В настройках репозитория (`Settings -> Secrets and variables -> Actions`) необходимо создать следующий секрет:
- **`DOCKER_PASSWORD`**: Personal Access Token (PAT), сгенерированный в настройках вашего профиля GitHub. Токен должен иметь право **`write:packages`**.

### 3.2. Подготовка сервера
На сервере в папке `/opt/BinanceCollector/` должен лежать файл `docker-compose.yml`. Копирование выполняется командой:
```powershell
# Выполняется в PowerShell на Windows
scp -P 2237 .\docker-compose.yml ваш_логин@ip_сервера:/opt/BinanceCollector/docker-compose.yml
```

## 4. Процесс развертывания

После первоначальной настройки, развертывание новой версии сводится к трем простым шагам:
1.  Внести изменения в исходный код.
2.  Сделать коммит: `git commit -m "Ваше сообщение"`.
3.  Отправить на GitHub: `git push`.

Пайплайн запустится автоматически.

## 5. Проверка и мониторинг после деплоя

После успешного завершения пайплайна, необходимо проверить состояние системы на сервере:

- **Проверить запущенные контейнеры:**
  ```bash
  docker ps
  ```
- **Смотреть логи приложения в реальном времени:**
  ```bash
  cd /opt/BinanceCollector
  docker compose logs -f app
  ```
- **Проверить состояние базы данных:** Подключиться через DBeaver и убедиться, что данные поступают.
