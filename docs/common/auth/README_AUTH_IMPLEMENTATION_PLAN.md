## 1. Границы ответственности модулей

### 1.1 DataManager UI (ASP.NET Core MVC)

Отвечает за:

* инициирование входа пользователя
* UI‑enforcement прав (страницы, компоненты, кнопки)
* отображение состояния системы (Normal / Degraded / Emergency)

НЕ отвечает за:

* принятие решений безопасности
* хранение прав

---

### 1.2 DataManager (Web API)

Отвечает за:

* окончательный enforcement permissions
* работу с `AuthorizationSnapshot`
* доступ к защищённым операциям

Является **единственным источником истины** для:

* проверки прав
* отказов доступа

---

### 1.3 Workers (Hangfire)

Отвечают за:

* выполнение system‑level задач

Правила:

* не знают о пользователях
* не проверяют permissions
* получают только валидированные команды

---

## 2. Точки встраивания логики

### 2.1 Аутентификация

* Интерактивный login — через IdP
* Результат аутентификации:

    * `ExternalSubjectId`
    * привязка к `UserIdentity`

---

### 2.2 Authorization Snapshot

Создание / обновление:

* при успешной аутентификации
* при ленивом refresh после восстановления IdP

Использование:

* на **каждом** защищённом запросе

---

### 2.3 Global System State

`SystemState` используется для:

* определения режима (S0 / S1 / S2)
* принятия решений:

    * разрешён ли первичный login
    * допустим ли Local Auth

---

## 3. Enforcement порядок (важно)

При каждом запросе к защищённому ресурсу:

1. Проверяется server‑side сессия
2. Проверяется текущий `SystemState`
3. Загружается актуальный `AuthorizationSnapshot`
4. Выполняется проверка permissions
5. При необходимости инициируется lazy refresh

Этот порядок **обязателен**.

---

## 4. Emergency‑режим (реализация)

### 4.1 Включение

* только оператором
* фиксируется в `SystemState`
* логируется в `AuditEvent`

### 4.2 Использование Local Auth

* только если `AUTH_MODE = S2`
* только operator accounts
* только для административных операций

---

## 5. Минимальный MVP (обязательный минимум)

Для завершённой версии auth‑системы:

* интерактивный login через IdP
* `User / UserIdentity / Role / Permission`
* `AuthorizationSnapshot`
* Degraded режим (fail‑open)
* Emergency режим (operator only)
* аудит auth‑событий

Без:

* сложных UI‑редакторов
* self‑service регистрации
* динамического управления ролями

---

## 6. Критические запреты

* Нельзя обходить `AuthorizationSnapshot`
* Нельзя давать Workers доступ к user‑auth
* Нельзя использовать Local Auth как пользовательский вход
* Нельзя выполнять массовый refresh прав
