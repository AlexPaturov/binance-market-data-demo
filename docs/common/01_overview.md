# Документация: 01 - Обзор проекта

## 1. Назначение системы

**`BinanceDataCollector`** — это автономный, самовосстанавливающийся и отказоустойчивый программный комплекс, предназначенный для непрерывного сбора и хранения рыночных данных с криптовалютной биржи **Binance**.

Основная задача системы — формировать чистое, полное и готовое к анализу хранилище данных, которое может служить фундаментом для:
- Бэктестинга торговых стратегий.
- Расчета технических индикаторов.
- Машинного обучения и предиктивного анализа.
- Визуализации рыночной активности.

## 2. Философия и ключевые принципы

Система спроектирована с учетом следующих принципов:

- **Автономность:** После первоначальной настройки система работает 24/7 без необходимости вмешательства человека.
- **Надежность:** Все компоненты спроектированы для автоматического перезапуска и восстановления после сбоев.
- **Целостность данных:** Встроенные механизмы аудита находят и заполняют любые пробелы в данных, которые могли возникнуть из-за простоев.
- **Производительность:** "Тяжелые" операции (массовая вставка, агрегация) вынесены на уровень базы данных для максимальной эффективности.
- **Автоматизация развертывания:** Обновления кода доставляются на сервер автоматически через CI/CD пайплайн, что минимизирует риск человеческой ошибки.

## 3. Основной алгоритм работы

Система функционирует как непрерывный конвейер данных, состоящий из четырех логических этапов:

1.  **Разведка (`Scanner`):** Система периодически сканирует рынок, чтобы определить список самых ликвидных и волатильных валютных пар. Это гарантирует, что собираются только релевантные данные.
2.  **Сбор (`Collector`):** Система в реальном времени подписывается на потоки сделок (тиков) для этих отобранных пар и сохраняет каждый тик в базу данных.
3.  **Агрегация (`Aggregator`):** Сырые тиковые данные непрерывно агрегируются в стандартные минутные свечи (OHLCV), формируя слой данных, готовый для технического анализа.
4.  **Аудит (`Auditor`):** Система регулярно проверяет целостность накопленных данных. При обнаружении "дыр" (пропущенных данных из-за простоев) она автоматически заполняет их, используя исторические API биржи.

## 4. Технологический стек

- **Язык программирования:** C#
- **Платформа:** .NET 8
- **База данных:** PostgreSQL 16
- **Среда выполнения:** Docker
- **Автоматизация (CI/CD):** GitHub Actions
- **Операционная система сервера:** Ubuntu Server 22.04 LTS
